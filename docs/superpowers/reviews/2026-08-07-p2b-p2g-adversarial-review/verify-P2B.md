## 2. Headline FALSE findings, ranked

2. **#33 / #33b — "WebKitGTK has no request-level host API."** `connect_resource_load_started` is bound and ungated (`web_view.rs:2523`); the parent spec of record (`…kiosk-browser-design.md:700`) names `resource-load-started` as *the* WebKitGTK SEC-10 mechanism. ## 3. Undeclared assumptions — stated as fact, unsupported by tiers 1–4

1. **WebKit content rules cover the app/asset origins at all.** A's Linux origins are custom schemes — `tauri://localhost` / `kioskasset://localhost` (P2-A:86,89,102-103), not http(s). B asserts "the bundled pages and the offline mp4 **must never be filtered**" and adds explicit `ignore-previous-rules` entries for them, presupposing that WebKit's content blocker applies to non-http(s) scheme loads. Nothing in the bindings settles this. No smoke scenario targets it directly.
2. **`data:` / `blob:` / hostless subresources survive Layer 1.** `NavPolicy::resource_allowed` deliberately allows every non-remote-origin URL, and `nav_policy.rs:110-117` says blocking inline `data:`/`blob:` "would only break legitimate bundled assets for zero egress benefit." B's Layer 1 is "block-everything rule first, then `ignore-previous-rules` for (a) allowlist patterns, (b) app/asset origins, (c) content origin" — `data:`/`blob:` appear in none of the three. This is a **tighter-than-Windows divergence not named** in B's divergence list (which claims "stricter, never looser" as blanket coverage but enumerates only path-scoped silence and clipboard).
3. **Same for Layer 2's CSP.** P1's `csp_policy` carries `img-src … data:` and `font-src … data:` (`nav_policy.rs:189,191`) precisely to keep bundled assets working. B's derivation is specified as "every allowlist pattern's origin, plus content origin + app origins" and its host test asserts "no path components survive" — `data:` is not mentioned. Same silent-breakage risk P1 refused to ship, in a different direction.
4. **The allowlist pattern strings are reachable at the point of derivation.** `NavPolicy.allowlist` is private; `Allowlist` exposes only `allows()` (`allowlist.rs:72`) and `invalid_patterns()` (`:67`) — **no accessor returns the source patterns**. Both new helpers need them. B specifies "turns the live allowlist into …" without naming the new accessor (on `NavPolicy` or `Allowlist`) or the alternative of threading `&Content.allowlist` through the config-apply path.
5. **`webkit2gtk-sys` needs its own feature declaration.** The store symbols are gated `#[cfg(feature = "v2_24")]` **in the sys crate** (`webkit2gtk-sys-2.0.2/src/lib.rs:5409,5475,5509`). B's feature paragraph declares features for `webkit2gtk` only and never mentions adding a direct `webkit2gtk-sys` dependency (none exists in `crates/kiosk-main/Cargo.toml`) or its `ffi/v2_24`-or-higher feature. The shim cannot compile without both.
6. **`REASON_EGRESS` visibility.** B explicitly calls out making `REASON_DOWNLOAD` `pub(crate)` but not `REASON_EGRESS` (`egress.rs:22`), which is equally private and equally needed by the Linux telemetry path.
7. **"operator dashboards see host-level egress blocks identically on both platforms."** Windows emits one `nav.blocked{egress}` per *actually-blocked request* (`egress.rs:129`, only on successful 403 substitution). Linux would emit one per *CSP violation report*. These are different populations — B concedes as much two paragraphs later ("path-scoped blocks … silent"). "Identically" is stated as fact and contradicted internally.
8. **`confirm_set_confirmed(true)` == "leave the page"** (#47b) and **returning `true` from the three signals produces suppression/handled** (#58). Both are WebKit runtime semantics asserted without a pinning mechanism; only the dialog case is partly covered by scenario 10.
9. **The `systemd-inhibit … cat` EOF-release chain** (#71) — "Exit symmetry comes free" is asserted, and the one smoke scenario that would touch it (12) is explicitly degrade-only, so nothing in the merge gate pins it. Its only pin is the deferred hardware checklist.
10. **`gtk::Application::inhibit` silently no-ops under cage/weston** (#70) — the sole justification for rejecting a shipped-API route (frame C2 prefers shipped APIs), with no cited evidence. The stronger, checkable reason — tao's `app` is `pub(crate)` (`tao-0.35.3/…/event_loop.rs:58`) and therefore unreachable — is not used.
11. **`InstallMissingMediaPluginsPermissionRequest` is safe to name** (#51b). Under the build's actual feature set it is `deprecated = "Since 2.40"`, and CI is `clippy -D warnings`. B lists it among the types the classifier maps to `Other` without noting the deprecation.
